# Test Suite Index

This directory contains the automated tests for FluxRig.

## Guidelines & Rules

### Strict Component Isolation
Each component (Mixer, Rack) executing within a test **must** run in its own dedicated subdirectory (e.g., `test/e2e_simple/mixer/`, `test/e2e_simple/rack/`).
- **Logs**: Must be written to `<component_dir>/logs/`.
- **Data**: Must be written to `<component_dir>/data/`.
- **Config**: Should ideally reside in or reference `<component_dir>`.

This prevents artifact collisions (e.g., locking same DB, overwriting logs) and allows clean parallel execution simulation.

## E2E Standardization Guidelines

To ensure a homogeneous testing experience, all E2E tests MUST adhere to the following rules:

1.  **Shared Utilities**: Source `test/e2e_utils.sh` and us `setup_workspace "test_name" "$BASE_DIR"`.
2.  **Temporal Workspaces**: each run generates a unique workspace (e.g., `work_test_20250101_120000`).
3.  **Symlinks**: The script creates a `work` symlink pointing to the latest execution for easy specific debugging.
4.  **Build System**: Use `make build` (running in root) to compile binaries.
5.  **Strict Isolation**: 
    - Logs must be written to `<work_dir>/<component>/logs/`.
    - Data must be written to `<work_dir>/<component>/data/`.

### Example Structure
```bash
source "${BASE_DIR}/../e2e_utils.sh"
setup_workspace "my_test" "$BASE_DIR"

...
# Use $WORK_DIR for all paths
./bin/fluxrig-mixer -c ... > "$WORK_DIR/mixer/logs/mixer.log"
...
```

## Running Tests
Each E2E test folder contains a `run.sh` script that executes the test in isolation.
```bash
./test/e2e_simple/run.sh
```

## Global Cleanup
To clean up all artifacts generated by tests (including temporal workspaces):
```bash
make clean
```
